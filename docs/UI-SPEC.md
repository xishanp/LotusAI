## 0. 全局玻璃铁律（定死 · 不可违反）

> 用户口径：**「以后都是按这种来做：全局玻璃加模糊加折射。这种你先搞规矩，给我定死。」**

任何一块"看起来像玻璃"的表面，**必须同时具备下面 4 样**，缺一样就不算玻璃、就是 bug：

| # | 要素 | 实现 | 缺了会怎样 |
|---|---|---|---|
| 1 | **背景模糊** | `blur()`（+ `vibrancy()` 提对比） | 玻璃变透明胶片，用户一眼看出来（已被投诉多次） |
| 2 | **边缘折射** | `lens()`，按下时按 `press` 从 0 长出来 | 没有玻璃质感，只是磨砂卡片 |
| 3 | **高光边** | `glassRim(shape, alpha)`（内描边）+ `Highlight` | 纯白背景上玻璃**完全看不见** |
| 4 | **霜面** | `onDrawSurface { glassVeilBrush() }` | 纯白底上"加白还是白"，面消失了 |

### 0.1 三条铁律

1. **一块玻璃 = 模糊 + 折射 + 高光 + 霜面。** 不许只做其中一样。
2. **折射永远 ± 动画配套。** 长按必须能从手指那一点"鼓"出折射 + 色散，松手弹回；
   静止态也要有基础折射，不能只在按下才像玻璃。
3. **模糊不许去掉，但只能糊"页面背景"。** 采样源里带着自己图标的玻璃（玻璃泡、独立按钮的
   图标层）**不许 blur** —— 糊了图标就变一坨灰。页面那层的模糊由外栏 / 玻璃壳负责（见 0.2）。

### 0.2 模糊只能糊"页面背景"，**绝不能糊到含图标的那份源**

真机截图抓出来的（v9 → v10）：玻璃的采样源里只要有**它自己的图标**，
对这份源做 `blur()` 就等于把图标抹掉。

| 症状 | 原因 |
|---|---|
| 底栏玻璃泡里的图标变成**一坨灰** | 泡的源 = `combined(页面, 四枚图标)`，v9 给它加了 `blur(5dp)` |
| 左上角历史钮变成一个**灰圆盘、图标不见了** | `blendAmbient` 时源 = `combined(页面, 图标)`，一起糊了 |

**规矩：**

1. **玻璃泡**（底栏 ③）：`effects` 里**只有 `lens`**，不许有 `blur` / `vibrancy`。
   页面的模糊由**外栏**（`blur(8dp)`）负责 —— 上游原版就是这么分的。
2. **独立按钮**（`blendAmbient = true`，如左上角历史钮）必须拆成**两层**：
   - ① 玻璃壳：只采样**页面背景** ⇒ `vibrancy() + blur(8dp)` + 霜面 + 描边；
   - ② 图标层：只采样 `iconBackdrop` ⇒ 1:1 清晰，按下才 `lens()` + 色散。
3. **嵌在父玻璃里的按钮**（输入条内那四枚）：不自己糊背景（否则等于给父玻璃挖洞），
   那块"面"由霜面 + 描边给；模糊由父玻璃（输入条 `glassPanel`）负责。

> 判定标准：图标**任何时候都必须清晰**，同时按下要能看到背后内容被糊掉。两者同时成立 = 对。

### 0.3 相融（Apple Liquid Glass 的 merge）—— **已下线，不要再做**

技术上实现过（玻璃颈 + 图标朝泡伸长 + 独立按压），真机上线后被用户否掉：

> 「不需要什么靠近扭那些，我只要前几个稳定版本就行」

现在底栏是**冻结的稳定版**：
外栏（模糊 + 折射 + 霜面 + 描边）+ 静态四图标 + 玻璃泡（滑动 + 按压缩放 + 折射 + 色散）
+ 拖动时外栏延迟跟随。**不要再往上叠相融 / metaball / 靠近扭。**

### 0.4 联动（不许"各动各的"）

> 用户口径：**「一个东西动了，它旁边的载体不应该也会轻微晃动吗？」**

**输入条（保留）**

1. 四枚按键各自有 press 状态（`LiquidGlassIconButton` 的 press 弹簧）；
2. 相邻按键被按住时，另外一枚**朝它伸长 22%**（`Modifier.merge`，锚点在朝向那一侧的边）；
3. 整条输入条被拽 1.5dp（`tug`）。

**底栏（用户点名只留稳定版）**

4. 玻璃泡滑动 + 按压缩放/折射/色散；拖动时**外栏延迟跟随**（`panelOffset` + spring 余震）；
5. **可见层与折射源层必须画同一份图标**，否则采样的源和眼睛看到的位置对不上 = **重影**；
6. ❌ 不做：图标邻位响应、单枚图标独立按压、玻璃颈相融（已下线，见 0.3）。

### 0.5 按压（指哪点哪）

**"不管按哪都往下沉"的真凶 = 上游 `LayerBackdrop` 的坐标补偿（v11 定案，有源码依据）**

上游 `backdrop/src/commonMain/.../backdrops/LayerBackdrop.kt`：

```kotlin
val offset = layerCoordinates.localPositionOf(coordinates)
translate(-offset.x, -offset.y) { drawLayer(graphicsLayer) }
```

它把"**采样源节点 ↔ 绘制节点**的坐标差"**反着**平移回去。这是给"采样页面背景"用的：
玻璃动、背景钉死在屏幕上（放大镜滑过纸面）。**采样自己录的图标时它就是个陷阱**。

v10 的写法：`graphicsLayer(pressTransform)` 只挂在**绘制节点**上、没挂在**录制节点**上 ⇒
两者坐标差 = 我们的放大 + 跟手位移 ⇒ 被反着补回去：

- "往手指方向倒"的位移被抵消（净剩 ~0.16×）；
- 反而多出一项 `-s·offset`：34dp 按钮、1.16 倍放大、手指在正中时
  `offset.y = 17dp×(1−1.16) = −2.72dp` ⇒ 图标净位移 **+3.1dp 向下**。
  按上半边只是小一点、方向不变 ⇒ 肉眼就是"**不管按哪都往下沉、还不跟手**"。

**修法（结构不许压平）**：变换提到**父层**，让"录制层"和"绘制层"成为同一个带变换父节点下的
**兄弟** ⇒ 坐标差恒为 0 ⇒ `-offset` 恒为 0。

```
Box(graphicsLayer(pressTransform)) {        // ← 变换只在这一层
  Box(alpha(0f).layerBackdrop(icon)) { 图标 }   // 录制层
  Box(drawBackdrop(icon))               { }    // 绘制层
}
```

玻璃壳（独立按钮）**相反**：它采样页面背景，`graphicsLayer` 必须留在 `drawBackdrop` 自己身上，
那个 `-offset` 正是我们要的。

**手感（用户口径：「要么原地放大，然后上下扭的时候往扭的那边紧」）**

1. `transformOrigin` **恒在中心**：1 → 1.13 倍**原地**鼓起，不朝任何固定方向跑；
2. **朝手指方向倒**：`translation = (触摸点−中心) × 2 × 4dp × press`，封 ±4dp。
   上边按下 ⇒ 向上仰；下边按下 ⇒ 向下沉；
3. ⚠️ 别再把支点锚在手指上：支点跟着手指时，放大会把图标朝手指**反方向**推出去，
   正好和"倒过去"互相抵消（实测净位移 < 1dp）＝"没反应、说不清往哪动"；
4. `press` 弹簧两向阻尼 ≥ 0.9，进度不越过 0..1（0.55 阻尼会缩到比静止还小 = "自己往下沉"）；
5. 高光跟手指：`fingerGlow()` 圆心跟着手指走 —— "按到哪、哪亮"。

**v11.1 —— 手指坐标"永不猜错"（修"全往上滑"）**

`PointerInputChange.position` 的语义**就是节点本地坐标**。v10 那版写了"能落在节点内就按本地算、
否则减掉节点在 root 的原点"，这个自适应分支是错的，而且是致命的：

手指按在按钮**边缘**（含触摸 slop）时本地坐标会略微越出 `0..size` ⇒ 条件为假 ⇒ 走"减原点"分支 ⇒
`本地坐标 − root 原点` = 一个**大负数**（输入条在屏幕底部，原点 y ≈ 1750+）⇒ `y/size` 被夹到 0 ⇒
**不管按哪都朝上**。用户实测原话："现在不往下滑了，全往上滑。"

现在（`resolvePointerFraction`）：**两种解释都算一遍，谁落在 -0.3..1.3 就用谁；都不合理返回 null（= 不倾斜）**。
宁可不歪，也绝不再往极值夹。函数注释里写了这条推理，别再"优化"回去。

**v11 模拟器实测（1080×2400 @2.625x，输入条 `+`）**

| 状态 | 图标质心 y | 相对静止 |
|---|---|---|
| 静止 | 1817.0 | — |
| 按**上**半边 (y=1782) | 1808.5 | **−8.5px（向上）** |
| 按**下**半边 (y=1852) | 1825.0 | **+8.0px（向下）** |

v11.1 把整段都扫了一遍（单调、对称、边缘不塌）：

| 按下 y | 质心 y | 相对静止 |
|---|---|---|
| 1776（**上边缘**） | 1807.3 | −9.7px |
| 1800 | 1812.9 | −4.1px |
| 1835 | 1821.1 | +4.1px |
| 1857（**下边缘**） | 1826.5 | +9.5px |

方向跟着手指、两侧对称 ⇒ 固定方向的"下沉"消失。

### 0.6 底色的铁律（踩过的坑，别再回去）

`LayerBackdropNode.draw` 的实现是 `draw { drawContent(); record { drawContent() } }`，
`drawContent()` **只画 `layerBackdrop` 之内的内容**。

- ❌ `Modifier.background(白).layerBackdrop(backdrop)` → 录进纹理的是**全透明** → 无模糊 + 折射残影
- ✅ `Modifier.layerBackdrop(backdrop) { Box(Modifier.background(白)) }`

> 上游 `NasGlass.kt` 里那一处就是 ❌ 的写法，**不要照抄**。

### 0.7 描边（v11）

**所有玻璃边一律走 `Modifier.glassRim(shape, alpha)`，不许再用 `Modifier.border`。**

`border` 把线宽**骑在轮廓上**（一半在形状外）——圆角/胶囊上外侧那半被抗锯齿啃成毛边，
读出来就是"一圈脏线 / 双层边"。用户原话：「你怎么在一块大玻璃上把它描边描得这么丑」。
`glassRim` 内缩半个线宽，边永远落在实心区内。

浓度口径（用户第二次否："描得太狠，有股塑料感"）：

- **`veil = 0` 的裸图标（输入条里的 `+` / `⚡` / `⇄`）不画边**：静止时必须是一枚干净图标，
  套一圈描边立刻变"塑料按键"；
- 大面（输入条 0.5、底栏 0.5、独立玻璃壳 0.55）、小玻璃面（发送键 `0.5×veil`）；
- `glassRimBrush` 底部深色已从 17% 砍到 11%，中段几乎为 0 —— 纯白底上玻璃靠**顶部那道白高光**活着。

### 0.8 启动页（v12）

**平台限制（模拟器 AOSP API35 实测，别再试别的路）**

| 想让系统启动页画 | 结果 |
|---|---|
| `windowSplashScreenBackground` = 纯色 | ✅ 生效 |
| `windowSplashScreenBackground` = layer-list drawable | ❌ 不画（那几百毫秒就是**一片白**） |
| 只给 `windowBackground`、不给 splash 属性 | ❌ 系统仍然铺白，不画我们的图 |
| `windowSplashScreenAnimatedIcon` = 图 | ✅ 画，但**画布固定 288dp、只显示中间 192dp 的圆**，其余全裁 |

判定方法是把一张"满幅网格 + 红线=画布边(576px) + 蓝圈=半径 192px"的测试图塞进
`windowSplashScreenAnimatedIcon` 冷启动截图量像素：

```
蓝圈包围盒   (288,948)-(791,1451)  504×504 px   = 192dp 圆
被裁网包围盒 (288,948)-(791,1451)  504×504 px   = 与蓝圈完全重合
红线(画布边)                              不可见
```

⇒ **系统那一帧里能显示的东西，硬上限就是"内切于 192dp 圆"**；图上再大也是白搭。
`windowSplashScreenBackground` 只认纯色，所以"系统层直接铺一张大立绘"这条路是死的。

**做法：系统帧尽量塞满 + App 层原地长大**

- `res/drawable-nodpi/lotus_splash_icon.png`：1152px 画布（= 2×288dp；系统依旧 FIT 到 288dp，
  只取中间 192dp 圆）。立绘相对原稿放大 **1.09 倍**，最远墨点到圆心 **186px < 192px**（程序化校验）
  —— 这是平台允许的最大值（再大头发尖会被圆硬切）；
- 系统层：`windowSplashScreenBackground` = 纯白，`windowSplashScreenAnimatedIcon` = 上面那张图；
- Compose 层（`ui/SplashScreen.kt`）：**同一张图、同样 288dp、居中**，所以系统层 → App 层是
  **逐像素同图**，立绘不会在交接处跳一下；
- `res/drawable/splash_background.xml`（API < 31 的 `windowBackground`）用同一个 288dp 尺寸。

**长大（v12）**：系统帧只能用 288dp 画布里的立绘（≈127dp 宽）。App 第一帧接住它之后：

1. 40ms 起手（几乎立刻，别让"小一帧"停在眼睛前面）；
2. 420ms 原地放大到 **2.3 倍** ⇒ 立绘 **≈290dp 宽**，与首页立绘（屏宽 0.74 ≈ 304dp）同档；
   应用名 25sp 从下方 140ms 后淡入；
3. 停到 660ms（从 App 第一帧算），整页 220ms 淡出（首页已在底下渲染好）。

模拟器实测（1080×2400 @2.625x）：系统帧立绘 331px → 长大末帧 **760×829px**（含应用名），
居中对齐（质心 x≈541 vs 屏幕中心 540）。

⚠️ 交接帧的尺寸/位置不许改（一改就跳）；缩放锚点必须留在画布中心。

⚠️ 已知：模拟器录屏里系统帧淡出 → App 帧之间会有 2 帧左右的纯白（平台退出动画 + 慢启动）。
真机启动快得多，暂不引入 `core-splashscreen` 去接管退出动画 —— 那是另一条风险线。

## 1. 视觉基调

| 项 | 决定 |
|---|---|
| 背景 | **纯白**，无渐变、无纹理、无颜色 |
| 材质 | Apple 风液态玻璃：白色高光边 + 浅灰描边 + 边缘折射 + 极柔灰阴影 |
| 颜色 | **零彩色**。纯黑白灰 |
| 立绘 | 黑白线稿（V1，`lotus-mascot-a1-ahoge-v1.png`） |
| 拒绝 | 彩虹/激光色边缘（已否决）、深色背景、紫色强调色 |

> 纯白背景上玻璃只能靠**边缘**显现（内部折射仍是白）。因此高光边 + 柔影是玻璃唯一的"存在感"来源。

```
│                          │     真机复验后用户要求**全部删除**
│ ┌──────────────────┬──┐  │
│ │ + 此刻，想说些什么？ ⚡ ⇄ ↗│  │  ← 玻璃输入条
│ └──────────────────┴──┘  │
│     [ 🏠  💬  🧭  👤 ]     │  ← 浮动胶囊，4 个图标，无文字
└──────────────────────────┘
```

**引导语：已全部删除，不要再加。**

历史：设计稿里排过 5 片"中间大两边小"的弧形玻璃砖（写文案 / 创意灵感 / 随便聊聊 /
帮我写作 / 学习问题），实机做出来用户连续否了两轮，最终口径是
**"把那 5 个提示词全弄掉，根本做不好看"**。代码里 `Suggestions` / `SuggestionArc` /
`SuggestionTile` / 手绘图标已连根删除。要再加，先问。

替代方案：立绘 + 问候语整体居中略偏上（上下留白按 1 : 1.05 分），其余留白交出去。

**输入框内控件（从左到右）**
`+` 附件 · placeholder · `⚡` 思考强度 · `⇄` 模型切换 · `↗` 发送

**底部导航**：4 个**纯图标、无文字**
`🏠 对话` · `💬 记忆` · `🧭 人设` · `👤 设置`（图标待细化）

底栏参数：`BarHeight = 52dp`、`InnerHeight = 44dp`、`BarWidth = 208dp`、`BarMargin = 96dp`；
输入条 `LotusComposerHeight = 56dp`、`ComposerBarGap = 22dp`。
（用户口径：两个条**都太低了，各往上移一个身位**。）

## 5. 待细化

- 4 个导航图标的具体造型（现在还是通用图标）
- 动画：高光随陀螺仪移动（陀螺仪那条还没做）
