# Lotus AI —— 总体规划

> 定位：**安卓端轻量 AI 聊天工具**。不是 agent，不做自主干活。

## 一、边界（不做什么）

| 不做 | 省什么 |
|---|---|
| ❌ 不挂工具 / function calling | 2k~5k token / 轮 |
| ❌ 不注入环境上下文（目录、git、时间戳） | 0.5k~2k / 轮，且保 prompt 缓存 |
| ❌ 不完整重放历史（滑窗 + 摘要替代） | 把平方增长压回线性，**省最多** |
| ❌ 不做 agent 循环（一次提问 = 一次模型调用） | 避免 20~80 倍调用次数 |
| ✅ **保留思考（reasoning），档位可调** | 质量优先；思考是一次性输出，不进上下文累积 |

## 二、架构

```
UI（Compose + 液态玻璃）
 聊天 / 角色 / 记忆 / 提示词 / 设置
        │
   ChatViewModel
        │
   ContextAssembler  ← 每轮唯一决定"发什么"的地方
   ① 提示词层（MD）      ② 核心记忆（有硬上限）
   ③ 会话摘要             ④ 召回事实记忆 top-N
   ⑤ 最近 K 轮原文
        │
   LlmClient（OpenAI 兼容 + 流式）
        │
   TokenLedger（记账）  MemoryWriter（触发式写入）
```

**核心原则：所有省 token 的逻辑集中在 `ContextAssembler` 一处**，不散落。

## 三、数据存储（纯文件，无数据库）

```
filesDir/lotus/
├── prompts/          提示词层（用户可编辑 MD）
│   ├── 00-core.md    全局规则（不可覆盖）
│   ├── 10-persona.md 当前角色 ← 换角色只换这一层
│   ├── 20-style.md   输出风格
│   ├── 30-scene.md   世界观（可选）
│   └── 90-user.md    用户覆盖（最高优先级）
├── personas/<id>.json + 立绘.png
├── memory/
│   ├── core.md       核心记忆（每轮带，硬上限）
│   ├── user.md       用户画像
│   └── daily/YYYY-MM-DD.md   情景记忆（按需召回）
├── conversations/<id>.json   消息 + 摘要
└── ledger/YYYY-MM.jsonl      token 记账
```

检索：启动时把 memory 加载进内存做关键词匹配。**条目上千再考虑 SQLite，现在不上。**

## 四、里程碑（每个都可独立验收）

### M0 ✅ 已完成
工程 scaffold、编译通过、APK 产出、液态玻璃 UI 栈、启动图标。

### M1 能聊起来
- LlmClient：OpenAI 兼容 + SSE 流式
- 消息列表真实渲染（Markdown、流式追加）
- 多会话：新建 / 切换 / 删除
- 设置页：`base_url` / `api_key` / `model` / `temperature` / 思考档位
- **验收**：能真的和模型对话，字是流式出来的

### M2 能量出来
- TokenLedger：每轮记录 input / output / cached / 耗时 / 模型
- 「用量」页：今日、本月 token 与估算成本
- **验收**：每轮数字可见

### M3 能省下来（上下文管理）
- ContextAssembler：滑窗 + token 预算 + 优先级裁剪
- 自动摘要：**滚动增量合并**（不是每次重摘全部）
- **验收**：50 轮以上长对话，每轮输入 token 保持有界，不随轮数线性增长

### M4 能改提示词
- 分层 MD 编辑器（App 内）
- 拼接预览 + **每层 token 数**
- 变量插值（时间等易变值放**尾部**，保缓存）
- 导入 / 导出
- **验收**：改完立即生效，能看到各层花了多少 token

### M5 人物设定
- 角色卡 CRUD + 立绘
- 切换角色只替换 `10-persona` 层 → 前缀大部分稳定，缓存不失效
- 兼容 SillyTavern Character Card 规格导入
- **验收**：导入一张社区角色卡即可直接使用

### M6 记忆框架
- `core.md` / `user.md`：每轮带，**硬上限**
- `daily/*.md`：情景记忆，**按需召回 top-N**
- **触发式写入**：用户说"记住" / 每 N 轮 / 会话结束 —— 不额外增加模型调用
- 记忆管理页：查看 / 编辑 / 删除
- **验收**：跨会话记得住；不记废话；不像图谱那样过度抽取

### M7 打磨
深浅色、字号、背景样式、对话导出、全文搜索。

## 五、已锁定的设计决策

| 决策 | 理由 |
|---|---|
| OpenAI 兼容协议 | 通吃各家；换 provider 只改 3 个字段 |
| ContextAssembler 集中管上下文 | 省钱逻辑必须只有一处 |
| 记忆 = 纯 MD 分层 + 内存检索 | 已验证 OpenClaw 做法 + 论文支持（LongMemEval, arXiv:2410.10813） |
| 不做知识图谱 / 向量库（M6 之前） | 手机上属过度设计，收益不成比例 |
| 思考保留、档位可调 | 不牺牲质量，但用户可控 |
| 不挂工具、不注入环境 | 这是与 Codex 类工具的本质分野 |
| 提示词前缀逐字稳定 | 保 prompt 缓存，最容易被忽略的省钱点 |
| 记忆写入触发式 | 避免把"一次提问一次调用"变成两次 |
